Every project opens on its **Overview** tab. It shows how the work is going, the latest status update, milestones, the people on the project and the records it is linked to. This page also covers the **Files** and **Activity** tabs.

## The project header

The header sits above every tab. It shows the project name, a star (**Star this project**), the health chip, the key and how many tasks are done, such as `OPS · 12 of 30 tasks done`. Owners and editors also see **Share**, which opens the people settings, and **Add task**.

The tabs are **Overview**, **Board**, **List**, **Table**, **Timeline**, **Calendar**, **Workload**, **Cycles**, **Triage**, **Files**, **Activity** and, for owners and editors, **Settings**. Tabs that do not fit fold into **More**. The **Triage** tab shows how many requests are waiting.

## What the Overview shows

| Panel | What it holds |
| --- | --- |
| **Status updates** | The update form for editors, then the update history |
| **Progress** | A ring of tasks done, the counts **Tasks**, **In progress**, **Done** and **Overdue**, and a bar of time used. **Reports** opens Dashboards for this project |
| **About this project** | The description. Editors can change it in place |
| **Milestones** | Key dates, with how many of their tasks are done |
| **Recent activity** | The latest changes to the project and its tasks |
| **Details** | **Owner**, **Stage**, **Dates**, **Space**, **Who can see it** and **Key** |
| **People** | Everyone on the project |
| **Linked records** | Customers, CRM deals and WMS records this project is for |
| **Goals** | Goals this project moves. Link one from the **Goals** page |

When the project is linked to a customer or CRM deal, a customer strip at the top shows the deal stage and warehouse activity. With KitStak Pulse, a strip shows the profit on linked jobs. See [link CRM and WMS records](/docs/projects/link-crm-and-wms-records).

An archived project shows a yellow note: **This project is archived. It’s read-only in lists and reports until you restore it.** Editors see **Restore in Settings**.

## Post a status update

A short weekly update keeps everyone in the loop without a meeting.

1. Open the project's **Overview**.
2. Under **Status updates**, pick **How is it going?**: **On track**, **At risk** or **Off track**.
3. Write what happened since the last update, anything blocking you, and what is next.
4. Optional: change the **Project stage**: **Planning**, **In progress**, **On hold** or **Done**.
5. Select **Post update**.

The update sets the project's health and stage, and the first line of the note shows in the header. Members get a note in their inbox. The history shows the last three updates; select **Show all** to see the rest.

> **Note:** Only owners and editors can post updates. Everyone on the project can read them.

## Add and complete milestones

1. Under **Milestones**, select **Add**.
2. Type a name, such as `Go live`, and pick a date.
3. Select **Add**.

Select the circle next to a milestone to mark it reached, or open its menu and pick **Mark as reached**, **Mark as not reached** or **Delete milestone**. A milestone with no linked tasks shows **No tasks linked**. When the project has dates, a small timeline above the list shows each milestone and today.

## The Files tab

The **Files** tab lists everything attached to the project and its tasks.

1. Drag files onto the page, or select **Upload files**.
2. Find a file with **Find a file**, or filter by **All**, **Images**, **Documents** or **Other**.
3. Switch between **List** and **Grid**.

Each file shows whether it is a **Project file** or **On a task**. Files can be up to 25 MB each. Commenters and above can upload.

## The Activity tab

The **Activity** tab lists every change to the project and its tasks, grouped by day. Use **Show** to pick **Everything**, **Comments**, **Task changes**, **Project changes**, **Files and links** or **Automations**. Changes made by an automation are marked **Automation**.
