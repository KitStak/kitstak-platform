Each project has its own **Settings** tab. It holds the project's details, its workflow, labels, custom fields, people and roles, and the archive, copy and delete actions. Owners and editors see the tab; some parts are for owners only.

## Before you start

- You need the Editor or Owner role on the project to open **Settings**. Changing the key, the visibility and people needs the Owner role.

## Open project settings

1. Open the project.
2. Select the **Settings** tab, or **Project settings** from the project's menu on the Projects page.
3. Pick a section on the left: **General**, **Workflow**, **Labels**, **Custom fields**, **People & roles** or **Archive & delete**.

## General

| Setting | What it does |
| --- | --- |
| Color and icon | How the project looks in the sidebar and lists |
| **Project name** | The name everyone sees |
| **Key** | The short code in task ids. Changing it renames every task id, such as `OPS-12` to `LIVE-12`. Owners only |
| **Space** | The space the project sits in, or **No space** |
| **Stage** | **Planning**, **In progress**, **On hold** or **Done**. **Done** moves the project to the **Completed** tab |
| **Start date** and **Due date** | The project's dates. They set the pace for health and burn-down |
| **Owner** | The person who leads the project |
| **Who can see it** | **Workspace** or **Members only**. Owners only |

Select **Save changes** after changing the name or key, or **Cancel** to undo them. Other settings save as you change them.

The key follows the same rule as when you create a project: 2 to 6 letters or numbers, starting with a letter, and not used by another project.

## Workflow, labels and custom fields

- **Workflow** holds the statuses. See [statuses and workflow](/docs/projects/statuses-and-workflow).
- **Labels** holds the labels. See [labels](/docs/projects/labels).
- **Custom fields** holds the custom fields. See [custom fields](/docs/projects/custom-fields).

## People & roles

The section shows everyone on the project and their role. On a project the whole workspace can see, members get notified and can be assigned. On a private project, only these people can see it.

1. To add people, pick the **Role for new people**, then select **Add people** and pick teammates.
2. To change someone's role, pick a new one next to their name.
3. To remove someone, select the bin next to their name.
4. To leave a project yourself, select **Leave**.

| Role | What it allows |
| --- | --- |
| **Owner** | Can do everything, including people and delete |
| **Editor** | Can add and change tasks and settings |
| **Commenter** | Can view and comment |
| **Viewer** | Can only look |

Every project needs an owner. You can't change or remove the last owner; make someone else owner first. Only project owners can add people or change roles. If you leave a private project, you won't see it anymore unless someone adds you back.

The **Share** button in the project header opens this section.

## Archive, copy and delete

| Action | What it does |
| --- | --- |
| **Archive** | Hides it from Projects, the sidebar and reports. Nothing is deleted. Find it under **Projects > Archived**. **Restore** puts it back |
| **Make a copy** | Same columns, labels, fields, milestones and tasks, in a new project |
| **Save as a template** | Your team can start new projects from this setup in the New project gallery |
| **Delete this project** | Removes it and its tasks for everyone. Owners only. You can undo right after |

To save a template, enter the **Template name** and optional **What it’s for**, choose whether to **Include the tasks**, and select **Save template**. See [project templates](/docs/projects/templates).
